SLIDE COPY FORMAT (applies to every text key in keys object):
1. Write for the slide, not a script. Use fragments, not complete sentences.
2. Prefer punchy phrases: "4 hours/week; manual reconciliation" not "Teams lose four hours every week because they reconcile invoices manually."
3. Drop articles and helper verbs when the meaning stays clear.
4. One beat per key by default. Join at most two related beats with semicolons only when the presentation key instruction and maxWords allow it.
5. Typical length: 3-12 words per key unless the key's maxWords and instruction allow more fragments (see presentation keys).

Do not: write infodeck-style bullet dumps, essay-style prose, stand-up comedy, sarcasm, hype without source backing, clickbait phrasing, or emojis.

Good vs bad examples:
- Bad (infodeck): "Legacy APIs block integration; no single source of truth; ops teams firefight daily; manual workarounds everywhere."
- Good (reinforcement): "Legacy APIs; no single source of truth"
- Bad: "Our platform will save customers significant time by automating their workflow."
- Good: "Automated workflow; hours back every week"
- Bad: "We chose a microservices architecture because it scales independently."
- Good: "Microservices; independent scale"
