PRESENTATION SLIDE PRINCIPLES (applies to every key in keys object; rationale only):

These slides support a live talk. They are not an infodeck, email pre-read, or handout. A speaker will explain context; on-screen copy must complement that voice.

1. Complementary channel: keys hold audience-facing reinforcement (headline, label, or post-point summary), not the full narrative from the DOCX.
2. Do not steal the narrative: never front-load every point the speaker will make. If the audience could read the key and skip the talk, rewrite shorter.
3. Minimalism (glance media): prefer the fewest words that land one beat. Use semicolon clusters only when the presentation key instruction and maxWords allow multiple fragments.
4. One beat per key unless the key instruction explicitly allows 2-3 fragments.
5. Visual-first: for slides with image keys, keep paired text keys especially short; image search phrases should evoke the concrete scene or emotion of that beat (specific, not generic stock tropes).
6. Not a handout: omit detail that belongs in the source DOCX. Do not write prose suitable for distribution without a presenter.

Good vs bad (same underlying fact):
- Bad (infodeck): "Teams lose four hours weekly reconciling invoices manually; legacy APIs block automation; no single source of truth."
- Good (reinforcement): "Four hours/week; manual reconciliation"
